# Dagitali GitHub Defaults v0.6.0

Version 0.6.0 aligns shared maintenance conventions and improves community triage and validation
evidence. This minor-release candidate was prepared on 2026-10-07 (America/New_York); the date
records preparation, not tagging or publication.

- Status: planned candidate; no local `v0.6.0` tag exists at preparation.
- Intended tag: `v0.6.0`; final integration, release approval, and hosted evidence remain pending.
- Comparison baseline: the local [v0.5.1] tag. The clean pre-preparation checkout differed in 31
  files; this record includes the complete source-tree difference plus release-preparation docs.
- Candidate identity: the inspected checkout plus these documentation edits. Link final reviewed
  commit and run evidence before tagging; no final candidate revision is asserted here.

## Change Scope

Dependency maintenance explicitly targets `develop` for version updates across Actions, Python, Node
fixtures, and pre-commit. Fixture directories, separate validation-tool grouping, automatic labels,
and staggered UTC schedules remain intact; security updates retain default-branch routing.

Generated release notes gain generic label categories and aliases, including breaking changes,
deprecations, features, fixes, documentation, validation, and maintenance, with a final catch-all
and no exclusions. Community forms add optional diagnostics, examples, documentation impact, and
feature-surface triage. Existing field IDs, mandatory responses, labels, and support/private
reporting routes are preserved. Device, permission, connectivity, and sync prompts are conditional.

All reusable workflows and public composite actions gain consistent YAML document boundaries. Python
CDK runtime setup composes the same-revision setup action in setup-only mode; early guards, Node
setup, installation order, compatibility policy, and post-install reporting remain intact. Library
CI and manual candidates report validation-tool versions; the composite CDK fixture reports
Node.js/npm and dependencies. Candidate run titles now identify the exact ref and commit.

Popo YAML validation covers all top-level `.github/*.yml` configuration. Regression coverage
protects CDK setup forwarding and candidate identity. Contribution, support, branch-protection, PR,
testing, and release guidance clarify evidence, compatibility, delivery, and impact-based version
selection. Preparation also reconciles maintained v0.5.1 tag status without rewriting its historical
checks.

No dependency pins, caller starters, runtime matrices, job identities, credentials, deployment,
publishing workflows, or hosted settings are changed by this release scope.

## Compatibility and Configuration

No breaking workflow/action interface changes or new deprecations. Paths, inputs, types, defaults,
outputs, permissions, and required-check identities retain their previous contracts. Optional form
fields add triage capability without adding mandatory responses; generated-note categorization and
Dependabot version-update targets intentionally change repository maintenance behavior.

Consumer owners can adopt a reviewed immutable revision after validation; existing pinned callers do
not update automatically. Copied forms and local configuration require separate reconciliation. No
mandatory caller rewrite or copied-starter migration is introduced. Generic command inputs remain
trusted code execution, not a sandbox. See [workflow contracts] for the public surface.

## Support Boundary

No supported-runtime or platform expansion. Python/CDK same-revision composition remains
GitHub.com-only; Swift CI remains Swift Package Manager validation, not signed Xcode distribution.
Private reporting, notifications, ownership, and branch enforcement require separate hosted
configuration. Optional triage prompts do not impose Apple tooling or assume Discussions exists.

## Artifact Contracts

No artifact contract changes. Distribution, diagnostics, audit, and inventory names, contents,
retention, upload conditions, and returned metadata remain unchanged. Version diagnostics and run
titles improve logs and navigation, not release-artifact integrity guarantees. This library has no
own package distribution. See [Validation](#validation) for outstanding evidence.

## Publication, Adoption, and Rollback

Shared tagging and publication rules are in [release operations].

Not published by this preparation. No tags, pushes, branch integrations, consumer reference edits,
or hosted configuration changes are performed. Library push validation does not publish releases,
consumer packages, or infrastructure; manual candidate checks remain non-publishing.

Adopt in a representative consumer first using a reviewed immutable reference, then expand only
after recording its results. Rollback restores each consumer's previously verified reference and any
separately adopted local forms/configuration. [v0.5.1] is the comparison baseline, not an assertion
of a universally known-good target. No moving major tag is introduced.
