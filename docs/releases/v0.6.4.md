# Dagitali GitHub Defaults v0.6.4

Version 0.6.4 refreshes the Node CDK validation fixture's library dependency. This patch-release
record is dated 2026-10-07 (America/New_York). Tag and publication dates have not been independently
verified.

- Version identifier: `v0.6.4`; this record does not verify tagging, release approval, or publication.
- Comparison baseline: the local [v0.6.3] tag. Before release-document preparation, the only source
  difference was one fixture dependency pin update.
- Validation identity: results below concern the release-preparation worktree, not a subsequent tag.

## Change Scope

Update `aws-cdk-lib` from 2.271.0 to 2.272.0 in `tests/fixtures/node-cdk/package.json`, matching the
Python CDK fixture's existing library version. The Node fixture's `constructs` pin, private package
designation, test script, and source files remain unchanged. Release documentation adds this record
and updates the archive and changelog.

No workflow declarations, public composite actions, starter templates, community defaults, hosted
settings, or root validation dependency requirements change.

## Compatibility and Configuration

No shared workflow/action interface changes or new deprecations. Consumers manage their own CDK
dependencies: this fixture update requires no caller rewrite, dependency upgrade, or copied-starter
migration. Existing pinned library references do not update automatically. See [workflow contracts]
for the public surface.

The fixture installs a newer CDK library when its dependencies are resolved. Matching version pins
across fixtures does not prove equivalent synthesis behavior or compatibility with every consumer.

## Support Boundary

No declared support-boundary changes. The fixture dependency refresh does not expand supported Node
versions, runner platforms, AWS services, or deployment behavior. The library remains non-deploying;
ordinary repository checks require no AWS credentials.

No artifact contract changes. Distribution, diagnostic, audit, and inventory names, formats,

## Publication, Adoption, and Rollback

Shared tagging and publication rules are in [release operations].

Tagging, GitHub Release publication, and consumer adoption are not verified for v0.6.4.
Documentation preparation performs no tags, pushes, publication, deployment, or hosted settings
changes. Library validation remains non-publishing and does not deploy consumer infrastructure.

No consumer dependency rollout is required for this fixture-only pin update. Maintainers should
verify fixture tests and synthesis before treating the new dependency as tested. A fixture
regression can be addressed by restoring its prior pin through a reviewed follow-up change. Consumer
reference rollback restores each caller's previously verified immutable revision; [v0.6.3] is the
comparison baseline, not proof of a universally known-good target.

## Known Limitations and Follow-Up
