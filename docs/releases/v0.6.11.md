# Dagitali GitHub Defaults v0.6.11

Version 0.6.11 improves starter selection and shared-automation incident recovery guidance, corrects
outdated adoption instructions, and refreshes read-only operational evidence. This documentation-only
patch preserves public automation contracts and does not change consumer callers or hosted settings.

- Version identifier: `v0.6.11`.
- Record date: 2026-10-07 (America/New_York), identifying documentation preparation rather than a
  verified tag or publication date. The operational review occurred on 2026-10-08 UTC, October 7
  locally.
- Comparison baseline: the local v0.6.10 tag; scope is the adoption/recovery documentation and
  operational-evidence changes, plus associated release records, since that version.
- Validation identity: local results concern the preparation checkout, not a later release tag.

## Change Scope

The [starter catalogue] maps all six starters to their purpose, prerequisites, consumer substitutions,
declared job permissions, and canonical workflow contracts. It remains navigational: declarations
own input/artifact details, and the consumer-owned Python publishing job links its existing setup
guidance. The documentation index and Actions guide link the catalogue.

The [incident runbook] covers private triage, affected immutable revisions and consumer discovery,
approved containment, corrected immutable publication, validated consumer migration or rollback,
and coordinated disclosure/closure. It builds on the existing release and security policies without
introducing response deadlines, automatic caller changes, or permission to publish a release.

The [operational review] refreshes the library and representative consumer's hosted drift/caller
evidence, plus API/file observations of inherited versus local community defaults. The adoption
checklist and consumer inventory link the new evidence, preserving prior snapshots and pending
owner, scheduling, reporting, and escalation decisions. Hosted-audit instructions now correctly
identify the existing Popo v0.6.3 pin and matching documentation; the Actions guide removes obsolete
claims about unreleased interfaces and previously verified early tags.

No workflows, actions, starters, fixtures, dependency pins, validation configuration, community
policy terms, or hosted settings change. No generic validator is duplicated in this library.

## Compatibility and Configuration

No compatibility or configuration changes. Public paths, inputs, outputs, permissions, runners,
required-check identities, and artifact declarations remain unchanged. No consumer migration or
dependency reinstall is required by this documentation release. Incident containment, publication,
and caller changes described in the runbook still require explicit authorization.

## Support Boundary

No support-boundary changes. Catalogue prerequisites summarize existing contracts, not newly tested
platforms. API-observed community files and library fixture runs do not establish rendered default
behavior, monitored reporting, external adoption, or effective enforcement against bypass actors.

## Publication, Adoption, and Rollback

Shared tagging and publication rules are in [release operations].

Tagging and GitHub Release publication are not verified for v0.6.11. Released wording is prepared
at the maintainer's request, not a publication receipt. The runbook describes approval boundaries;
it does not authorize incident actions, consumer rollout, or automatic archival.

No runtime rollback is needed for this documentation-only patch. Correct records through reviewed
follow-up changes while preserving dated evidence and immutable tags. The v0.6.10 library run is a
comparison baseline, not a proven external-consumer rollback target. During an actual incident,
owners must verify a proposed rollback reference is unaffected and compatible before using it.

## Known Limitations and Follow-Up

Confirm responsible owners, review dates, evidence-age limits, monitored reporting recipients, and
an approved conduct escalation contact. Complete displayed-default verification in a suitable
browser session and obtain matching consumer evidence if the consumer elects to adopt this library.
The [consumer inventory] and [operational review] retain these decisions and gaps without inventing
approval. See [Validation](#validation) for outstanding release evidence and confirmed hosted drift.
