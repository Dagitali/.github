# Dagitali GitHub Defaults v0.6.13

Version 0.6.13 aligns shared pull request guidance with generic contribution conventions and adds
maintainer references to the issue templates. This community-default documentation patch preserves
public automation contracts and issue submission behavior.

- Version identifier: `v0.6.13`.
- Record date: 2026-10-07 (America/New_York), identifying documentation preparation rather than a
  verified tag or publication date.
- Comparison baseline: the local v0.6.12 tag; scope includes the committed community-template
  changes and accompanying release records in this checkout.
- Validation identity: local preparation-checkout results, not tagged-revision evidence.

## Change Scope

The [pull request template] organizes compatibility and risks, validation, deployment and rollback,
and documentation and decisions into generic sections. CLI and automation compatibility prompts
cover public interfaces and required-check identities. Conditional packaging guidance requests the
affected repository's build, artifact-integrity, and clean-installation checks rather than imposing
a package manager or project-specific Make targets. Validator changes retain read-only guarantees
and consumer-independent behavior where those are documented contracts.

The checklist explicitly covers changed-behavior tests, repository safety invariants, breaking
changes, deprecations, and migration steps. Existing privacy, accessibility, localization, hosted
evidence, rollback, and authorization safeguards remain. Inapplicable and skipped checks require
explanations rather than being presented as successful results. Project-specific commands remain in
each consumer's contribution guidance.

The [issue templates] add GitHub documentation references in maintainer comments only. No fields,
labels, prefixes, requiredness, blank-issue settings, or support/security routes change. No reusable
workflows, composite actions, starters, dependencies, fixtures, or hosted settings change. Removing
Popo's local PR template is a separate consumer change, not part of this library release.

## Compatibility and Configuration

No automation compatibility or configuration changes. PR headings and checklist wording change;
maintainers with tooling that parses PR descriptions should review the revised sections. Existing PR
descriptions are not rewritten. No caller-reference migration or dependency reinstall is needed.

Consumers with a local PR template retain their override. Consumers using organization defaults
receive the template from the default branch, not from a pinned workflow reference. Repository-local
contribution requirements still apply; the generic checklist does not replace them.

## Support Boundary

No support-boundary changes. Guidance remains language- and platform-neutral, with packaging, CLI,
automation, UI, accessibility, localization, and privacy prompts conditional on the affected scope.

## Publication, Adoption, and Rollback

Shared tagging and publication rules are in [release operations].

Released wording is prepared at the maintainer's request; tagging and GitHub Release publication are
not verified. Default-template adoption follows integration into the organization repository's
default branch. No consumer files or caller references are changed by this release preparation.

For a template regression, apply a reviewed forward fix or restore the affected declarations from
the v0.6.12 baseline without retargeting immutable tags. Review the effect on inheriting consumers;
workflow-pin rollback does not select a community-template revision.
