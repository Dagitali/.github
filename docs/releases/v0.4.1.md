`feature/record-hosted-adoption-evidence`; the date records preparation, not tagging or publication.
The changes document observed settings, successful runs, and operational gaps without changing
automation or hosted configuration.

## Highlights

- Records an authenticated, read-only assessment of all adoption-checklist items for two
  repositories.
- Separates verified reporting enablement, workflow results, and effective protections from missing
  settings and inaccessible notification preferences.
- Identifies the consumer's missing shared caller and hosted CODEOWNERS error without claiming
  fixes.
- Connects the checklist to the evidence record and indexes this documentation-only patch candidate.

## Change Scope

The complete feature scope since `v0.4.0` adds `docs/adoption/2026-10-05-hosted-review.md`, links it
from `docs/ADOPTION.md`, and records the audit in `CHANGELOG.md`. This preparation additionally
creates this release record and updates the archive and dated patch entry. It also acknowledges the
existing v0.4.0 tag in the archive and changelog without changing that tag or its preparation-time
release document.

The audit records disabled library private reporting, enabled consumer private reporting, unverified
recipient notification preferences, successful library fixture execution, and the absence of a
shared-library caller in the representative consumer. It distinguishes unprotected library branches
from consumer legacy review protections with no selected status checks and administrator exemption.
GitHub also reports an invalid owner in the consumer's CODEOWNERS file.

These are dated observations, not remediation. No workflows, actions, starter templates, tests,
dependencies, public interfaces, or consumer files change in this patch.
