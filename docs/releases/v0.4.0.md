release candidate was prepared on 2026-10-05 on `release/0.4.0`; the date records preparation, not
publication. Its feature and documentation scope is integrated, but tagging, hosted validation, and
release approval remain pending.

## Highlights

- Adds PR-only dependency review and manual Python dependency audit/inventory starters, each with
  matching chooser metadata. These reuse existing workflows rather than introducing new
  implementations.
- Adds a default private vulnerability form and affected-project security/support routing.
  Committing these defaults does not enable private reporting, verify notifications, or configure
  support.
- Improves public project discovery, first-contribution guidance, coordinated security report
  handling, and explicit inheritance/override responsibilities without new response commitments.
- Adds consumer adoption and ownership/exception/lifecycle guides, a documentation index, workflow
  selection guidance, and consistent bottom-of-document Markdown reference definitions.
- Adds focused routing/starter regression coverage and NumPy-format Python fixture documentation.

## Compatibility and Configuration

No reusable workflow/action paths, inputs, defaults, outputs, runner requirements, permissions, or
artifact contracts are changed by the inspected feature comparison against v0.3.0. The breaking
publishing removal and GitHub.com-only Python/CDK composition belong to v0.2.0, not this release. A
comparison of the preparation base against v0.3.1 confirms unchanged workflow/action declarations;
recheck the final tagged diff before approval.

Consumers adopt the new starters explicitly, replace SHA placeholders with a reviewed available
revision, and configure project-specific inputs. PR dependency review is not a merge-queue
prerequisite; manual inspection is optional evidence. Copied callers need separate edits from
library SHA updates. Review local community-policy overrides because inherited defaults may not
apply.

## Support Boundary

Existing runtime and platform boundaries remain unchanged; see [workflow contracts]. Python/CDK
same-revision action composition requires GitHub.com, Swift CI targets Swift Package Manager, and
CDK checks do not deploy or perform credential-dependent lookups. Installation executes project
code; inspection must run trusted revisions without secrets. Configurable environments and committed
policies are not proof of hosted compatibility or effective enforcement.
