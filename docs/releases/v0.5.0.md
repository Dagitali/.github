# Dagitali GitHub Defaults v0.5.0

Version 0.5.0, tagged on 2026-10-06 (UTC), adds configuration-driven, read-only hosted drift
auditing through Popo v0.5.2. This minor release was prepared and its documentation refreshed on
2026-10-06. That preparation date is not a publication date. The additive maintainer capability
leaves existing shared workflow/action interfaces unchanged.

- Status: local annotated `v0.5.0` tag verified during v0.5.1 preparation on 2026-10-06; its
  metadata records `2026-10-06T14:19:38-04:00`. Remote tag availability and GitHub Release
  publication were not verified during this documentation preparation.
- Tag: `v0.5.0`; the results below retain their original preparation-checkout boundaries.
- Comparison baseline: [v0.4.1], whose local tag exists. The reviewed scope is the committed feature
  changes and original release notes after that tag, plus this documentation refresh. The [hosted CI

## Change Scope

The complete feature scope after `v0.4.1` changes `Makefile`, `pyproject.toml`,
`requirements-dev.txt`, `tests/test_popo_integration.py`, `docs/CONTRIBUTING.md`, and `CHANGELOG.md`,
and adds `docs/adoption/hosted-drift-audit.md`. Release preparation adds this record, indexes it,
and corrects maintained v0.4.1 tag-status wording without rewriting the tag or historical results.

Generic configuration loading, API inspection, and exception validation live in Popo. This library
supplies `[tool.popo.hosted]` expectations for `Dagitali/.github` and `Dagitali/aws-cdk-static-site`.
The inventory expects private reporting, secret scanning/push protection, default-branch CODEOWNERS,
issue-form labels, and protected `main`/`develop` with named validation checks. It is a minimum desired
baseline, not evidence of enforcement or authorization to change settings.

No reusable workflows, composite actions, starters, community defaults, or consumer files change.
No new scheduled audit, automatic repair, deployment, or publishing workflow is introduced.

## Compatibility and Configuration

No breaking compatibility changes. Shared paths, inputs, defaults, outputs, runner requirements,
permissions, required-check job identities, concurrency, and existing artifact contracts retain
their previous declarations; see [workflow contracts]. Existing callers need no migration or copied
starter update for this maintainer-only feature.

Maintainers install the updated pinned requirements, then run:

```sh
make hosted-audit
make hosted-audit HOSTED_AUDIT_ARGS='--format json'
```

`HOSTED_AUDIT_ARGS` forwards CLI options and `REPOSITORY_ROOT` selects the inventory root. The
installed Popo command is `audit-github-settings`. Exit zero means all configured findings are
verified or excepted; exit one includes confirmed drift, unavailable evidence, expired exceptions,
or invalid configuration. Ordinary `make check` and pre-push remain independent of GitHub access. No
target installs tools implicitly or falls back to sibling source code.

## Support Boundary

The maintainer validation environment retains Python 3.13/3.14 support; preparation uses Python
3.14.7 on macOS. The audit targets github.com through authenticated `gh` GET requests and requires
read access sufficient for the selected metadata. Credentials are supplied through GitHub CLI, not
workflow inputs or repository configuration. GitHub Enterprise Server support is not added.

Required context names are checked against effective branch rules and legacy protection. Default-
branch CODEOWNERS presence and hosted errors are inspected; notification delivery, bypass actors,
review-count policy, source-App identity, merge queue execution, and shared caller execution are
outside this audit's evidence boundary. Desired configuration alone does not prove enforcement.

## Artifact Contracts

No workflow artifact names, retention, diagnostic upload behavior, or consumer download contracts
change. Text/JSON audit reports are printed to stdout; no report file is created automatically. JSON
includes UTC observation time and narrow findings with check IDs, statuses, details, and evidence
URLs. Saving an audit report is an explicit maintainer action, not release publication, an
enforcement attestation, or a notification-delivery receipt. This library remains non-packaged; the
Popo distribution is an external pinned validation dependency.

## Publication, Adoption, and Rollback

Shared tagging and publication rules are in [release operations].

The original preparation did not tag or publish; a local annotated `v0.5.0` tag now exists. This
maintained record does not establish remote tag availability or GitHub Release publication. No
branch rules, labels, reporting settings, notification preferences, or consumer callers are changed
or dispatched. No exceptions are approved in the inventory. Approval evidence and expiry remain
separate reviewed records, never automatic waivers for inaccessible evidence.

The feature and original release notes were committed in the release-branch baseline. Preparation
required review of its documentation refresh, final-commit validation, release-branch integration,
and explicit tag/publication authorization; the local tag alone does not verify those outcomes.
Preserve the existing immutable version tag and carry maintained documentation corrections in a
follow-up release. Consumers adopting the new audit should install the reviewed requirements and
verify their own inventory and read permissions before relying on findings.

`v0.4.1` is the source comparison baseline, not a universally verified consumer rollback target. To
undo this maintainer capability, restore the preceding reviewed tooling/configuration through a new
change and reinstall its pinned requirements; ordinary shared automation interfaces have not
changed. SHA-pinned consumers retain their previous reference unless they deliberately update it.

## Known Limitations and Follow-Up

- Audit results can reveal unresolved settings or access gaps; successful local checks do not
  resolve the existing operational adoption findings.
- The configured required contexts are a minimum baseline, not exhaustive review/bypass policy.
- Exception approvers and URLs are recorded attestations, not authenticated approval by this tool.
- Maintainers should reconcile final-commit evidence with [Validation](#validation) before changing
  this record's status and record authorized publication under [Publication, Adoption, and
  Rollback](#publication-adoption-and-rollback).
- Consumer owners should verify notification delivery and actual shared caller adoption separately;
  neither is covered by this audit's settings checks.
