# Dagitali GitHub Defaults v0.6.10

Version 0.6.10 clarifies the confirmed contribution licensing terms for Dagitali's automation
library. This documentation-only patch states MIT licensing for library contributions without
requiring a separate CLA or extending MIT licensing to consumer projects.

- Version identifier: `v0.6.10`.
- Record date: 2026-10-07 (America/New_York), identifying documentation preparation rather than a
  verified tag or publication date.
- Comparison baseline: the local v0.6.9 tag; scope is the contribution-terms clarification and
  associated release documentation since that version.
- Validation identity: local results concern the preparation checkout, not a later release tag.

## Change Scope

The library-specific [contribution terms] explicitly state that contributions submitted for
inclusion in `Dagitali/.github`, including documentation, are licensed under its [MIT License]. No
separate Contributor License Agreement (CLA) is required. Contributors must have authority to submit
their work and preserve applicable third-party licenses and notices.

The terms distinguish this library from other Dagitali repositories: consumers retain their own
licenses and contribution requirements, and using shared defaults, workflows, or actions does not
place a consumer project under MIT. The organization-wide contribution guide continues to defer to
the affected repository's terms and is unchanged.

No license file, workflows, actions, templates, fixtures, dependencies, validation configuration, or
hosted settings change. This release documents the maintainer-confirmed policy; it introduces
neither a CLA process nor an organization-wide license grant.

## Compatibility and Configuration

No automation compatibility or configuration changes. Public paths, inputs, outputs, permissions,
required-check identities, and caller references remain unchanged. No consumer migration or
dependency reinstall is required. Contributors to this library should review the explicit terms;
contributors to other repositories must follow those projects' own requirements.

## Support Boundary

No support-boundary changes. The contribution terms apply only to this library, not to every
repository that uses it. They do not establish consumer licensing or alter existing third-party
licenses and notices.
