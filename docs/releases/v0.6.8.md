# Dagitali GitHub Defaults v0.6.8

Version 0.6.8 adds read-only automation safety checks through pinned Popo v0.6.3, refreshes hosted
adoption evidence, and clarifies project-specific contribution terms. This maintenance patch
preserves the library's public workflow and action contracts.

- Version identifier: `v0.6.8`.
- Record date: 2026-10-07 (America/New_York), identifying documentation preparation rather than a
  verified tag or publication date.
- Comparison baseline: the local [v0.6.7 tag]; scope includes the committed library changes and
  release documentation since that version.
- Validation identity: local results describe the checkout tested, not a later tag or hosted run.

## Change Scope

The [October 7 hosted review] records read-only observations for the library and representative
consumer `Dagitali/aws-cdk-static-site`, preserving the October 5 snapshot. It distinguishes
confirmed settings drift from unverified notification delivery and external caller adoption. The
[consumer inventory] records revision/run evidence, ownership gaps, pending review dates, and
follow-up without automatically archiving consumers or assigning maintainers.

The root `pyproject.toml` adds `[tool.popo.safety]` configuration for library/starter workflows and
both source/committed Node CDK manifest-to-lockfile pairs. The [automation safety guide] explains
the checks and their activation through the published dependency pin and Make gates. `make
repository-safety` runs through both `lint` and `self-check`, covering ordinary `make check`,
pre-push, and existing CI/candidate gates. Consumer integration tests exercise actual configuration
and copied/committed fixture drift through the installed CLI. Adoption, audit, and documentation
indexes link these records. The organization-wide contribution guide clarifies that each affected
repository's license and contribution instructions determine terms; it introduces no blanket license
or CLA.

No workflow, action, starter, fixture, artifact declaration, or hosted setting changes. Generic
safety-check implementation is supplied by Popo's separate published release, not duplicated in this
library. Organization-profile starter-comment cleanup is already present in the comparison baseline
and is not new v0.6.8 scope.

## Compatibility and Configuration

Public workflow/action paths, inputs, outputs, runner requirements, permissions, required-check
identities, and artifact contracts remain unchanged. No caller rewrite or copied-starter migration
is required. Development setup now installs published Popo v0.6.3 through an immutable release pin;
existing validation environments must explicitly reinstall `requirements-dev.txt` before checking.

The safety table is enforced by `check-repository-safety` in both `lint` and `self-check`, as
described in the [activation gate]. Unapproved privileged triggers, direct event-data shell
interpolation, privileged head checkouts, and configured npm root inconsistencies fail the local
gate. No exceptions are approved. The checks remain read-only and do not implicitly install tools.
Existing caller-supplied command inputs remain trusted, not sandboxed.

These checks strengthen maintenance validation for this library; consumers do not automatically
inherit its Make gate or Popo configuration by referencing a reusable workflow or action.

## Support Boundary

No support-boundary changes. No runtime, runner image, platform, package-manager, or consumer layout
support is added. Static safety policy is not a sandbox or complete npm dependency-graph audit;
existing hosted `npm ci` and synthesis remain necessary. Observations concern the named repositories
at the recorded review time, not organization-wide enforcement or a completed consumer rollout.

## Publication, Adoption, and Rollback

Shared tagging and publication rules are in [release operations].

Tagging and GitHub Release publication are not verified for v0.6.8. Preparing these documents does
not publish Popo, change hosted settings, or roll out caller references. The local/CI gate
configuration activates checks through the already-published Popo pin; hosted execution of this
library revision remains unverified. Consumers retain ownership of their reporting configuration,
rules, notifications, and callers. Release wording does not establish publication or adoption.

Correct documentation or validation policy through reviewed follow-up changes without retargeting
immutable tags. The [v0.6.7 tag] is the comparison baseline; its fixture run does not prove a
known-good external consumer rollback target. Any rollback must restore the dependency pin, Make
gates, and policy coherently through a reviewed library revision; downgrading only Popo to a release
that ignores safety configuration silently weakens validation. No consumer caller-reference
migration is required. Preserve dated audit history when recording subsequent observations.

## Known Limitations and Follow-Up

The [activation gate] is wired locally; maintainers still need final-revision hosted evidence.
Responsible maintainers and review dates remain unassigned in the [consumer inventory]; obtain those
decisions rather than inferring them from CODEOWNERS or commit authors. Remediation and notification
verification require separately authorized operations. See [Validation](#validation) for outstanding
release and adoption evidence.
