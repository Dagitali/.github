# Dagitali GitHub Defaults v0.6.2

Version 0.6.2 updates pinned GitHub Actions dependencies across six workflows. This patch-release
record is dated 2026-10-07 (America/New_York). Tag and publication dates have not been independently
verified.

- Version identifier: `v0.6.2`; this record does not verify tagging, release approval, or
  publication.
- Comparison baseline: the local [v0.6.1] tag. Before release-document preparation, the only source
  differences were six action-reference updates in `.github/workflows/`.
- Validation identity: results below concern the release-preparation worktree, not a subsequent tag.

See the [changelog] for this version's concise change list.

## Change Scope

- Update `actions/setup-node` from v6 to v7.0.0 in `aws-cdk-ci.yml` and library `ci.yml`.
- Update `actions/setup-python` from v6 to v7.0.0 in `python-package.yml`,
  `python-dependency-audit.yml`, and `python-sbom.yml`.
- Update `actions/dependency-review-action` from v4.9.0 to v5.0.0 in `dependency-review.yml`.

All six references remain pinned to full immutable commits. The public `actions/` implementations,
including setup-python-project's existing setup-python v6 pin, remain unchanged. Python CI, Swift
CI, manual candidate validation, starter templates, community defaults, and development dependency
requirements are unchanged. Release documentation adds this record and updates the archive and
changelog.

## Compatibility and Configuration

No library workflow/action input, default, output, path, permission, trigger, concurrency, or
required-check identity changes. Existing callers need no syntax rewrite; consumers pinned to an
older library revision do not update automatically. See [workflow contracts] for the public surface.

These are upstream major-version updates, not proof of identical runtime behavior. The [setup-python
v7 release] removes its `pip-install` input; the three updated workflow steps do not use that input.
The [setup-node v7 release] records cache/runtime implementation updates and removal of a dummy
authentication-token export. Hosted behavior of the updated pins remains unverified here; validate
affected caller setup, caching, package checks, inspection, and dependency review before adopting a
new immutable library reference.

## Support Boundary

Declared runner labels, Python/Node selections, and supported library platforms remain unchanged.
The [dependency-review v5 release] changes the action runtime to Node.js 24 and requires Actions
Runner v2.327.1 or newer. This is the action's execution runtime, not a change to a consumer's
selected Python or Node version. Verify runner compatibility before adoption; this record does not
establish support for additional self-hosted runner configurations.

## Validation

Interpret these results using the [evidence boundaries] and [reading guide].

- Scope inspection on 2026-10-07: the clean pre-preparation checkout differed from local v0.6.1 in
  six workflow files, each changing only one pinned action reference and its version comment.
- Local preparation gate: Passed `make check release-changelog RELEASE_VERSION=0.6.2` on 2026-10-07
  with Python 3.14.7 and Popo 0.5.2 against the release-preparation worktree before this evidence
  update. Ruff lint/format, actionlint, automation contracts, strict mypy, all 127 pytest tests,
  local Markdown links, and the dated changelog check passed.
- Upstream release-note review: Reviewed the linked version-specific action releases for
  compatibility context; this is not execution evidence for the library workflows.
- Updated remote-action execution, hosted CI, manual candidate matrices, and representative consumer
  callers: Not run or inspected during preparation; no hosted workflows were dispatched. Local tests
  do not execute the downloaded JavaScript actions on GitHub runners.
- Tagged-revision validation: Not verified; no local v0.6.2 tag existed at scope inspection.

Use the [testing guide] and [release policy] for final-revision checks. Preparation results must not
be attributed to a later commit or tag.

## Artifact Contracts

No library artifact contract changes. Distribution, diagnostic, audit, and inventory names,
contents, retention, upload conditions, and returned metadata retain their declared configuration.
Unchanged declarations do not establish identical output from upgraded upstream dependencies; see
[Validation](#validation) for execution gaps.

## Publication, Adoption, and Rollback

Shared tagging and publication rules are in [release operations].

Tagging, GitHub Release publication, and consumer adoption are not verified by this record.
Documentation preparation performs no tags, pushes, publication, or hosted configuration changes.
Library validation remains non-publishing and never deploys consumer infrastructure.

Validate affected workflows in a representative consumer before expanding adoption of a reviewed
immutable library reference. Rollback restores each consumer's previously verified reference; a
library fix can restore affected action pins through a reviewed follow-up change. [v0.6.1] is the
comparison baseline, not proof of a universally known-good consumer target. Existing immutable tags
remain unchanged.

## Known Limitations and Follow-Up

The maintainer should verify the updated actions on hosted runners and reconcile final-revision and
consumer evidence with [Validation](#validation), recording release approval and verified
tag/publication outcomes separately from released-version wording. Consumer owners must confirm
runner compatibility and affected workflow results before rollout.
