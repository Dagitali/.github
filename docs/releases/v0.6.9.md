# Dagitali GitHub Defaults v0.6.9

Version 0.6.9 makes the consumer lifecycle inventory actionable with immutable caller evidence,
explicit ownership and scheduling gaps, and a review queue. This documentation-only patch flags
stale evidence for owner review without automatically archiving repositories.

- Version identifier: `v0.6.9`.
- Record date: 2026-10-07 (America/New_York), identifying documentation preparation rather than a
  verified tag or publication date. The inventory refresh occurred on 2026-10-08 UTC, October 7
  locally.
- Comparison baseline: the local v0.6.8 tag; scope is the lifecycle-documentation changes and
  associated release records since that version.
- Validation identity: local results concern the preparation checkout, not a later release tag.

## Change Scope

The [consumer inventory] now records lifecycle roles, responsible-maintainer and
contact-confirmation status, immutable source/revision links, successful caller evidence and its
scope, separate caller and hosted-settings review dates, review requests, and pending owner-approved
schedules. An open review queue identifies the next ownership, scheduling, and adoption decisions
for the library and representative consumer `Dagitali/aws-cdk-static-site`.

Review flags distinguish current, stale, missing, and inaccessible evidence. Updating an inventory
or observing unrelated CI does not reset evidence age. The [maintenance guide] connects these
records to owner-led lifecycle decisions without adopting automatic archival. Existing dated
hosted-settings snapshots are preserved; this refresh does not reverify those settings.

No workflows, actions, starter templates, fixtures, dependencies, Popo configuration, or hosted
settings change. Review tracking is maintained documentation, not a new automated audit command.

## Compatibility and Configuration

No compatibility or configuration changes. Public paths, inputs, outputs, permissions, runner
requirements, required-check identities, and caller references remain unchanged. No consumer
migration or dependency reinstall is required. Owners still need to confirm contact/access, next
review dates, and evidence-age limits; documenting a gap does not approve an assignment or deadline.

## Support Boundary

No support-boundary changes. Library fixture success is not external consumer adoption or proof of
current hosted enforcement. A consumer using local actions remains an adoption candidate until its
actual immutable library reference and matching successful caller are verified.

No artifact contract changes. The inventory and review queue are maintained Markdown records, not

## Publication, Adoption, and Rollback

Shared tagging and publication rules are in [release operations].

Tagging and GitHub Release publication are not verified for v0.6.9. Released wording is prepared at
the maintainer's request; it does not establish publication, assign owners, or complete consumer
adoption. No repository is archived, workflow disabled, or caller reference updated by this change.

No runtime rollback is needed for this documentation-only patch. Correct records through reviewed
follow-up changes, retaining earlier evidence and dated decisions rather than retargeting tags. The
v0.6.8 fixture evidence is a library baseline, not a proven external-consumer rollback target.

## Known Limitations and Follow-Up

Both records need responsible owners and agreed review dates/evidence-age limits. The representative
consumer also needs an explicit adoption decision and, if adopting, a full-SHA caller reference and
successful matching run. The [open review queue] records these gaps without inventing approvals. See
[Validation](#validation) for remaining release and operational evidence.
